## 🤔 Embedding Dimension은 왜 786이지?

GPT-2 Small(117M)은 **embedding dimension이 768**입니다.

이 값은 단순히 임의로 정해진 게 아니라, **BERT-base와의 호환성과 연산 효율성**에 기반합니다.

### 1. BERT-base에서 시작된 관례

BERT-base 모델은 hidden size 768, 12개 attention head를 사용합니다.

GPT-2는 Transformer Decoder 블록을 기반으로 하기에,

**동일한 차원 구조를 유지하면 pretraining 기법과 하드웨어 최적화를 재활용하기 용이**합니다.

### 2. 768 = 64 × 12 구조

- Head 수: **12개**
- 각 Head dimension: **64**
- 전체 hidden size: 12 × 64 = **768**

즉, 병렬적으로 나누기에도 깔끔한 구조입니다.

### 3. GPU 연산 효율성

768은 GPU의 **warp size(보통 32)** 의 배수입니다.

행렬 곱 연산 시 thread 병렬화가 효율적으로 이뤄지기 때문에

속도와 메모리 측면 모두에서 유리합니다.

> 정리:
> 
> 
> 768은 “적당히 크면서도 GPU 병렬화 효율이 좋은 최소 단위”이자
> 
> “12-head 구조와 자연스럽게 맞아떨어지는” 수입니다.
>

## 🤔 어휘 크기 는 왜 50,257일까

GPT-2의 어휘(vocabulary) 크기는 **50,257개**입니다.

이 수는 다음과 같이 구성됩니다 

**50,000 + 256 + 1 :**

1. **50,000개**: Byte-Pair Encoding (BPE)으로 학습한 병합 토큰들
2. **256개**: 모든 가능한 바이트 값 (0-255) - BPE의 기본 단위
3. **1개**: `<|endoftext|>` 특수 토큰 (문서 구분용)

Byte-Level BPE를 사용했기 때문에

모든 가능한 바이트가 토큰화 가능한 단위가 되어,

문자 인코딩 문제 없이 어떤 텍스트라도 표현할 수 있습니다.

## 🤔 GPT에서는 Bias를 잘 안 쓰는 이유?

Transformer의 Linear 레이어나 Attention projection에서

**bias=False**를 자주 보셨을 겁니다.

왜 그럴까요?

### 1️⃣ Layer Normalization이 이미 “shift”를 제공

LayerNorm은 아래와 같은 수식을 가집니다:

LayerNorm(x)=γx−μσ+β\text{LayerNorm}(x) = \gamma \frac{x - \mu}{\sigma} + \beta

LayerNorm(x)=γσx−μ+β

여기서 **β(bias)** 항이 이미 “shift” 역할을 합니다.

따라서 Linear layer에 별도의 bias를 더하면 **중복**됩니다.

```python
# LayerNorm이 이미 shift + scale을 수행
x = LayerNorm(x)         # γ * (x - μ) / σ + β
x = Linear(x, bias=False)  # 중복 bias 제거

```

### 2️⃣ 메모리 효율성

파라미터 수가 수억~수십억 개에 달하는 모델에서는

bias도 무시 못 할 메모리 차지를 합니다.

hidden_size=12288이라면, Linear마다 bias가 12k개씩 붙는 셈이니까요.

### 3️⃣ 경험적 결과

실험적으로도 bias를 제거해도 성능 저하는 거의 없으며,

일부 모델(LLaMA, GPT-J)은 오히려 더 안정적 결과를 보였다고 합니다.

## 🤔 Multi-Head Attention vs Feed-Forward

Transformer의 핵심은 “관계 학습”과 “표현 확장”입니다.

두 역할을 나눠 맡는 것이 바로 **Multi-Head Attention**과 **Feed-Forward Network(FFN)**입니다.

---

### Multi-Head Attention = **“토큰 간 관계 학습”**

```python
# 여러 head가 서로 다른 관계를 학습
Head 1 → 문법적 관계 (주어-동사)
Head 2 → 의미적 관계 (동의어, 반의어)
Head 3 → 위치적 관계 (거리 기반)
Head 4 → 대명사-명사 공참조 관계

```

예를 들어,

> “The cat sat on the mat”
> 

이라는 문장에서 “cat”은 “sat”, “mat”과 각각의 의미적 관계를 맺습니다.

즉, MHA는 **토큰 간 정보 교환의 핵심 메커니즘**입니다.

---

### Feed-Forward Network = **“개별 토큰의 심화 표현”**

```python
# 각 토큰을 독립적으로 비선형 변환
x = Linear(x, 4*d_model)
x = GELU(x)
x = Linear(x, d_model)

```

- Attention으로 모은 정보를 바탕으로
    
    각 토큰을 “혼자서 깊게 생각하게” 만듭니다.
    
- 보통 hidden size의 **4배 확장(768→3072)** 을 사용합니다.

---

### Transformer Block의 흐름

```python
x = x + MultiHeadAttention(x)  # 관계 파악
x = x + FeedForward(x)         # 표현 확장

```

| 구성 | 초점 | 비유 |
| --- | --- | --- |
| Multi-Head | 토큰 간 관계 | 여러 사람에게 의견 물어보기 |
| Feed-Forward | 각 토큰의 심화 처리 | 모은 정보를 혼자 깊게 생각하기 |

---

## 🤔 Output Projection의 역할

Multi-Head Attention의 마지막 단계에서는

각 head의 출력을 단순히 이어붙이는(concat) 것만으로는 충분하지 않습니다.

그래서 **출력 프로젝션(out_proj)** 이 필요합니다.

### 1️⃣ Head 간 정보 통합

```python
# head 별 64차원 × 12개 → 768차원
context = torch.cat(head_outputs, dim=-1)
context = self.out_proj(context)  # (768, 768)

```

- 단순 concat이면 head 간 정보가 독립적
- projection을 통해 **모든 head의 정보를 혼합·재조합**

### 2️⃣ 추가 표현력 제공

out_proj는 학습 가능한 가중치이므로

단순 결합이 아닌 **비선형적 feature 융합**을 학습합니다.

## 🤔 파라미터 수: 1.24억 vs 실제 1.63억

GPT-2 Small의 공식 파라미터 수는 **약 124M(1.24억)** 입니다.

하지만 직접 모델을 구현하거나 `sum(p.numel() for p in model.parameters())`를 찍어보면

**약 163M(1.63억)** 이 나옵니다. 왜 그럴까요?

### 원인: Weight Tying 여부

GPT-2 논문은 **“입력 임베딩(embedding)”과 “출력 projection(weight)”을 공유(weight tying)** 합니다.

```python
# tied weights (원래 GPT-2 방식)
lm_head.weight = wte.weight

```

하지만 구현에서 이를 분리하면

출력 projection용 Linear가 **768 × 50257 ≈ 38M** 파라미터를 추가로 갖습니다.

> 따라서:
> 
> - **Tied weights** → 약 **124M**
> - **Untied weights** → 약 **163M**

성능 측면에서 tied/untied는 큰 차이는 없지만,

일부 실험에서는 **untied** 구성이 약간 더 나은 perplexity를 보이기도 합니다.
