uv는 Rust로 작성된 초고속 python 패키지 설치 및 프로젝트 관리 도구입니다.

### 동기 비동기, 블로킹 논블로킹

#### Blocking / Non-Blocking

- 블로킹은 다른 요청의 작업을 처리하기 위해 현재 작업을 block(waiting) 하는 것

- 논블로킹은 block(waiting)하지 않는 것\
  즉, 블로킹/논블로킹은 전체적인 작업의 제어권(흐름)을 막냐 막지 않느냐의 차이입니다.

#### 동기/ 비동기

동기는 작업 시간을 함께 맞춰서 실행한다는 뜻,\
즉, 요청한 작업에 대해 완료 여부를 따져 순차적으로 처리하는 것을 의미합니다\
비동기는 요청한 작업에 대해 완료 여부를 따지지 않음 따라서 자신의 다음 작업을 그대로 수행합니다\
여러개의 요청 작업을 순차적으로 처리 하냐 아니냐의 차이입니다\
동기는 요청한 작업에 대해 순서가 지켜지고, 비동기는 순서가 지켜지지 않습니다

<img width="851" height="457" alt="스크린샷 2025-11-21 오후 8 44 18" src="https://github.com/user-attachments/assets/8dd40343-8aba-474f-a751-f313f52e6e77" />


비동기의 경우 I/O 작업과 같은 오버헤드가 큰 작업을 수행할 때, 해당 I/O와 관련 없이 다음 작업을 수행할 수 있다면, 응답 시간을 줄이는데 큰 이점이 있습니다

예를 들어, 요청에 대한 서버의 작업 중 DB 쿼리를 수행하는 작업이 있을 경우\
이 작업을 동기로 수행하면 데이터베이스에서 응답이 올 때 까지 대기해야 합니다\
이러면 다른 요청은 처리하지 못하므로, 대규모 트래픽이 발생하게 되면, 애플리케이션의 성능이 크게 저하될 수 있습니다\
하지만 비동기로 작업을 수행하게 되면, 데이터베이스 응답이 올 때 까지 대기하지 않고 다른 요청을 동시에 처리할 수 있게 되므로 응답 시간에 이점이 있습니다

#### 동기/비동기 + 블로킹/논블로킹 조합

- 동기 + 블로킹 조합

다른 작업이 진행되는 동안 자신의 작업을 처리하지 않고 (Blocking), 다른 작업의 완료 여부를 바로 받아 순차적으로 처리하는 (Sync) 방식 다른 작업의 결과가 자신의 작업에 영향을 주는 경우에 활용할 수 있습니다.\
DB에서 데이터를 조회해야 다음 작업을 처리할 수 있는 경우를 생각하면 됨

손님 : 파스타 한 접시 주세요 → Sync\
(주방에서 파스타를 조리하고 손님은 테이블에서 기다린다) → Blocking\
직원 : 파스타 나왔습니다 → 작업 종료\
손님 : 티라미수 하나 주세요 → Sync\
(주방에서 티라미수를 준비하고 손님은 기다린다) → Blocking\
직원 : 티라미수 나왔습니다 → 작업 종료\
(손님은 식사를 시작한다) → 다음 작업

- 비동기 + 논블로킹 조합

다른 작업이 진행되는 동안에도 자신의 작업을 처리하고 (Non Blocking), 다른 작업의 결과를 바로 처리하지 않아 작업 순서가 지켜지지 않는 (Async) 방식 다른 작업의 결과가 자신의 작업에 영향을 주지 않은 경우에 활용할 수 있습니다.

작업량이 많거나, 시간이 오래 걸리는 작업을 처리해야 하는 경우 고려할 수 있습니다.\
예를 들어, 대용량 데이터를 처리하거나 많은 트래픽을 처리하는 서비스에서 한 작업이 처리되는 동안 다른 작업을 처리할 수 있으므로 전체적인 응답 시간을 줄일 수 있어 애플리케이션의 성능을 향상시킬 수 있습니다.

손님 : 파스타 한 접시 주세요 → Async\
손님 : 티라미수 하나 주세요 → Async\
(손님은 휴대폰을 보거나 대화를 나눈다) → Non-blocking\
(주방에서 파스타를 조리한다)\
(주방에서 티라미수를 준비한다)\
직원 : 티라미수 나왔습니다 (먼저 완성됨) → 작업 종료\
직원 : 파스타 나왔습니다 → 작업 종료

- 동기 + 논블로킹 조합

다른 작업이 진행되는 동안에도 자신의 작업을 처리하고 (Non Blocking), 다른 작업의 결과를 바로 처리하여 작업을 순차대로 수행 하는 (Sync) 방식

손님 : 파스타 한 접시 주세요 → Sync\
(주방에서 파스타를 조리한다)\
손님 : 파스타 나왔나요? → Non-blocking\
직원 : 아직 조리 중입니다\
손님 : 파스타 나왔나요? → Non-blocking\
직원 : 파스타 나왔습니다 → 작업 종료\
손님 : 티라미수 하나 주세요 → Sync\
(주방에서 티라미수를 준비한다)\
손님 : 티라미수 나왔나요? → Non-blocking\
직원 : 아직 준비 중입니다\
손님 : 티라미수 나왔나요? → Non-blocking\
직원 : 티라미수 나왔습니다 → 작업 종료\
(손님은 식사를 시작한다) → 다음 작업

- 비동기 + 블로킹 조합

다른 작업이 진행되는 동안 자신의 작업을 멈추고 기다리는 (Blocking), 다른 작업의 결과를 바로 처리하지 않아 순서대로 작업을 수행하지 않는 (Async) 방식

손님 : 파스타 한 접시 주세요 → Async\
(주방에서 파스타를 조리하고 손님은 테이블에서 기다린다) → Blocking\
직원 : 파스타 나왔습니다 → 작업 종료\
손님 : 티라미수 하나 주세요 → Async\
(주방에서 티라미수를 준비하고 손님은 기다린다) → Blocking\
직원 : 티라미수 나왔습니다 → 작업 종료\
(손님은 식사를 시작한다) → 다음 작업
