# 📝 오늘 배운 것

## 1️⃣ Transformer Embedding

문장이 주어졌을 때, 각 단어는 **고유한 인덱스(index)** 값으로 매핑됩니다.

이 인덱스들은 임베딩 레이어를 거쳐 **512차원 벡터**로 변환됩니다.

각 차원은 단어의 특징을 표현합니다.

예를 들어:

- “먹을 수 있는가?”
- “탈것인가?”
    
    같은 의미적 속성이 벡터 차원 속에 녹아들게 됩니다.
    

### 초기 상태

처음에는 완전히 **랜덤한 값**으로 시작합니다.

```
"사과" → [0.01, -0.03, 0.02, 0.01]
"바나나" → [0.02,  0.01, -0.01, 0.03]

```

> 💬 아무 의미 없는 숫자들의 집합!
> 
> 
> 모델이 학습하면서 의미 있는 벡터로 바뀌게 됩니다.
> 

---

### 2️⃣ 학습 과정

모델은 수많은 문장을 보며 단어 간 관계를 학습합니다.

```
"나는 사과를 먹었다"
"바나나는 노란 과일이다"
"자동차가 빠르게 달린다"

```

이 과정에서 모델은 **비슷한 문맥에 등장하는 단어들**을 관찰합니다.

역전파(Backpropagation)를 통해 예측 오차를 줄여가며 벡터 값을 조정합니다.

```
"사과" → [0.5, 0.8, 0.2, 0.6]
"바나나" → [0.4, 0.9, 0.3, 0.5]  (유사한 의미)
"자동차" → [0.9, 0.1, 0.8, 0.2]  (다른 의미)

```

---

### 3️⃣ 인덱스 값은 어디서 오나?

모든 학습 문장을 수집한 뒤, 등장하는 **모든 단어로 어휘집(Vocabulary)** 을 만듭니다.

```
{
 "나는": 0,
 "사과를": 1,
 "먹는다": 2,
 "바나나는": 3,
 "맛있다": 4,
 "학교에": 5,
 "간다": 6,
 "[PAD]": 7,
 "[UNK]": 8
}

```

이 어휘집은 학습 전에 **고정**되어 있으며, 새로운 문장이 들어오면 단어를 인덱스로 변환합니다.

```
입력: "나는 사과를 먹는다"
→ 인덱스: [0, 1, 2]
→ 임베딩:
   0번 → [0.2, 0.5, ...]
   1번 → [0.3, 0.8, ...]
   2번 → [0.1, 0.2, ...]

```

모르는 단어는 `[UNK]` 토큰으로 대체합니다.

```
입력: "나는 망고를 먹는다"
"망고를" → [UNK] → 인덱스 8

```

---

### 4️⃣ 실제 Transformer에서는?

Transformer는 **BPE(Byte Pair Encoding)** 같은 **서브워드(subword)** 단위를 사용합니다.

```
"먹는다" → ["먹", "는다"]
"먹었다" → ["먹", "었다"]

```

이 방식은 다음과 같은 장점이 있습니다:

- 어휘집 크기 감소
- 모르는 단어 처리 가능

예:

“먹었습니다” → ["먹", "었", "습니다"]

→ 각각은 이미 어휘집에 존재할 확률이 높습니다.

## 2️⃣ Positional Encoding (위치 인코딩)

Transformer는 RNN과 달리 문장을 **순차적으로** 처리하지 않습니다.

따라서 단어의 **순서 정보**가 손실될 수 있습니다.

이 문제를 해결하기 위해 **Positional Encoding**을 추가합니다.

### 핵심 규칙

1. **위치값은 시퀀스 길이에 관계없이 동일해야 한다.**
    
    (시퀀스가 달라져도 동일한 위치에는 같은 위치 벡터 사용)
    
2. **위치값이 너무 크면 안 된다.**
    
    너무 큰 값은 단어 의미 정보보다 커져서 학습을 방해함.
    

---

### 💡 왜 사인(sin), 코사인(cos)을 쓸까?

<img width="248" height="68" alt="스크린샷 2025-11-04 오후 4 10 07" src="https://github.com/user-attachments/assets/29b5a276-0cac-4143-b774-5bda96d3c583" />

1. 단순히 “1, 2, 3...”처럼 증가시키면 시퀀스 길이에 따라 값이 달라져 1번 규칙을 위반합니다.
2. 정규화(normalization)를 해도 여전히 시퀀스 길이에 따라 달라집니다.

이를 해결하기 위해 **사인/코사인 함수**를 사용합니다.

- 범위: `[-1, 1]`
- 주기적 패턴: 긴 문장에서도 일정한 주기로 위치 차이를 유지
- 서로 다른 차원마다 **다른 주기**를 부여해 중복 방지

즉, 위치 인코딩 벡터는 스칼라가 아니라 **단어 벡터와 같은 차원의 벡터**입니다.

---

### 💡 왜 Concatenate 대신 Summation을 쓸까?

- **Concatenate**: 임베딩과 위치정보가 완전히 독립된 공간에 존재 → 연관성 약함
- **Summation**: 같은 공간에서 단어 의미 + 위치 정보를 함께 학습 가능
- **추가 이점**: 메모리와 연산 효율 향상

> 단, GPU 자원이 충분하고 모델이 매우 클 경우 Concatenate도 가능.
>

## 3️⃣ Attention 메커니즘

**Attention**은 “어떤 단어에 집중할지”를 결정하는 핵심 메커니즘입니다.

---

### 1. Attention Score 계산

각 단어가 다른 단어에 얼마나 주의를 기울일지를 수치화합니다.

```
Score = Q × Kᵀ

```

(Q: Query, K: Key)

이 행렬곱은 단어 간 **유사도(similarity)** 를 의미합니다.

---

### 2. Scaling & Softmax

Key 벡터의 차원 `d_k` 에 대해 `√d_k` 로 나누는 이유는?

> 큰 값이 Softmax에서 과도하게 강조되는 현상을 방지하기 위해서입니다.
> 
> 
> 값을 줄여주면 Gradient가 더 고르게 살아남습니다.
> 
> 👉 “Gradient 살리기 대작전”
> 

그 후 Softmax로 확률화해 중요도를 계산합니다.

---

### 3. Value 가중합

Attention Score를 Value와 곱해 더하면,

각 단어는 문맥 속 의미를 반영한 **새로운 표현**을 얻습니다.

```
Attention(Q, K, V) = softmax(QKᵀ / √d_k) × V

```

예:

- “은행” + “돈, 계좌” → 금융기관 의미
- “은행” + “나무, 공원” → 식물 의미

---

## 4️⃣ Multi-Head Attention

<img width="366" height="263" alt="스크린샷 2025-11-04 오후 7 40 14" src="https://github.com/user-attachments/assets/7290d555-888b-4dda-a3e4-e332d000f3d2" />

입력 벡터(512차원)는 여러 개의 Head로 나뉘어 각각 다른 시각에서 Attention을 계산합니다.

```
입력 (512차원)
 ├─→ Head 1 (64차원) → Q₁, K₁, V₁ → Attention₁
 ├─→ Head 2 (64차원) → Q₂, K₂, V₂ → Attention₂
 ...
 └─→ Head 8 (64차원) → Q₈, K₈, V₈ → Attention₈
 ↓
Concat → 512차원 → Linear 변환 (W_O)

```

각 Head는 **다른 관계나 패턴**에 집중합니다.

예를 들어:

- Head 1: 문법적 관계
- Head 2: 의미적 유사성
- Head 3: 감정적 맥락 …

이렇게 병렬로 여러 관계를 학습함으로써,

Transformer는 문장을 훨씬 풍부하게 이해할 수 있습니다.
